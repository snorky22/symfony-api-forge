# symfony-api-forge: notes for Claude

Symfony bundle `snorky22/symfony-api-forge` (MIT, namespace `Snorky22\ApiForge`) that generates services for
REST APIs and their webhooks from API documentation (curl commands, JSON examples, events tables).
GitHub: https://github.com/snorky22/symfony-api-forge (public, default branch `master`). Released: tag `v0.1.0`.

## Design decisions (made by the user, keep them)

- **Lenient import, strict generation.** Importers turn docs examples into editable YAML descriptors and list
  every guess under `review`; `api-forge:generate` validates strictly and never guesses.
- **Regenerate, never edit generated code.** Fixes go in the descriptors; existing descriptor values always
  win over re-imports. Generated files carry the marker "Generated by api-forge:generate".
- **Group by resource type**, not by URL path: nested routes become methods of the parent resource.
- **Arrays + PHPDoc array shapes** (`@phpstan-type`), not DTOs.
- **Reusable bundle**, not a project template. The generated code depends only on `Snorky22\ApiForge\Core`;
  the bundle itself is a dev tool (commands).

## Layout

- `src/ApiForgeBundle.php`: services, commands, `api_forge` config (`descriptor_dir`, `namespace`,
  `source_dir`, `config_dir`; defaults `config/api`, `App\Api`, `src/Api`, `config/packages`).
- `src/Core/`: runtime (resources, JSON:API, pagination, `ApiException`, `Webhook/` signed request parser
  and consumer).
- `src/Dev/`: importers (`Api/Import`), curl parser, descriptor schema/loader/store, generator, naming,
  `LenientJsonDecoder`, `ArrayShapeGenerator`.
- `src/Command/`: `api-forge:import`, `import-object`, `import-webhook`, `generate`, `json-to-php`,
  `make:resource`, `make:webhook`, `call`.
- `src/Core/Rest/`: hand-written REST resources (CRUD interfaces, traits, `AbstractRestResource`), no generated
  code; `src/Dev/Rest/ResourceMaker.php` writes them for `api-forge:make:resource`, in `src/API` (`App\API`,
  config `api_forge.rest`). `src/Dev/Webhook/WebhookMaker.php` (signature schemes list `SCHEMES`, enriched with
  experience) writes hand-written webhooks for `api-forge:make:webhook`, in `src/API/<Api>/Webhook`.
- `examples/lemonsqueezy/`: an application's files for Lemon Squeezy (descriptors, generated code and
  config, hand-written webhook consumer). Autoloaded as `App\` in dev only.
- `tests/`: unit tests, `tests/App/TestKernel.php` (bundle + example), `tests/console`, `tests/Fixtures/`
  (docs examples supplied by the user).
- `docs/`: user documentation; the root `README.md` is the index.

## Working on it

```bash
vendor/bin/phpunit
vendor/bin/phpstan analyse   # phpstan.dist.neon: level 6, the REST resources and their maker for now
php tests/console api-forge:generate lemonsqueezy --dir=examples/lemonsqueezy/config/api --output=examples/lemonsqueezy
php tests/console api-forge:make:resource   # writes to test-API/src/API (git-ignored scratch app)
php tests/console api-forge:call Paddle\\Prices list   # a real request (tests/console: env dev, .env.local)
```

- `test-API/` is the user's git-ignored scratch application for hand-written REST resources: the test kernel
  sets `api_forge.rest.source_dir` to `test-API/src/API`, autoloads `App\API\` from it (autoload-dev) and
  autowires its classes, and imports `test-API/config/packages/*.yaml` (`rest.config_dir`: the scoped clients the
  command writes; the directory is tracked, a new file rebuilds the container). The user deletes these files as they
  like; never commit them. Not loaded in the `test` environment (the tests must not depend on it). `.env.local` (the
  user's API keys) is git-ignored: never read or stage it.
- `tests/console` runs the test kernel in the `dev` environment: real HTTP requests, `.env.local` loaded (Dotenv).
  PHPUnit runs `test`, where the HTTP clients answer from `ApiMock`. Don't run `api-forge:call` against a real API
  yourself: it sends the user's keys; let the user run it.

- After any generator change, regenerate the example: `ApiGenerateCommandTest` fails if it is out of date.
- Update `docs/` and the root `README.md` in the same step as the code, and check that documented snippets
  run. Record user-facing changes in `CHANGELOG.md`.
- Keep `use` statements sorted alphabetically; match the existing style (short docblocks, `\sprintf`).
- The shell is zsh: unquoted variables are not word-split (use `xargs`/arrays); `grep` is aliased to ugrep
  (use `command grep` for backreferences).
- Commit or push only when the user asks.
