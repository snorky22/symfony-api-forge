# Commands

All commands are development tools, provided by the bundle. Run `bin/console <command> --help` for the
details. The default directories come from the `api_forge` configuration (see the README).

## `api-forge:import`

Imports an endpoint from a curl command, and optionally its example response, into the descriptors.

```bash
bin/console api-forge:import <api> <curl-file> [--response=<json-file>]
```

| Option | Default | |
|---|---|---|
| `--response` | none | File with the example JSON response |
| `--resource` | first path segment | Resource name |
| `--operation` | inferred from method and path | Operation name |
| `--force` | | Replace an existing operation with the same name |
| `--dir` | `config/api` | Descriptor directory |

Supported curl syntax: single, double and `$'...'` quotes, `\` line continuations, a leading `$ `
prompt, `-X`/`--request` (also `-XPOST`), `-H`, `-d`/`--data`/`--data-raw`/`--data-binary`, `--json`,
`-u`, `-G`, `--url`, `--opt=value`. Unknown options are listed in the review notes.

## `api-forge:import-object`

Imports resource object examples ("The customer object" in the docs) as the `object` shape of a
resource. Full JSON:API documents are accepted too (API responses, webhook payloads): their `data` is
used. Several examples are merged into one shape: differing types become unions (`int|float`), keys
missing from some examples become optional.

```bash
bin/console api-forge:import-object <api> <resource> <json-file>... [--force] [--dir=...]
```

An existing object shape is kept, unless `--force` is given.

## `api-forge:import-webhook`

Imports webhook documentation into `config/api/<api>/_webhooks.yaml`.

```bash
bin/console api-forge:import-webhook <api> [--events=<markdown-file>] [--payload=<json-file>]...
```

| Option | |
|---|---|
| `--events` | Markdown table of events: event name (in backticks), object sent, description |
| `--payload` | Example payload (repeatable); gives the event name location and, for JSON:API, the event resource |
| `--event` | Event name of the payload, when it cannot be read from it (single `--payload`) |
| `--dir` | Descriptor directory (default `config/api`) |

The resource of each event is derived from the object name of the table ("Subscription invoice
object" → `subscription-invoices`). For JSON:API payloads, the data is compared to the resource object
shape, or gives it when the resource has none.

## `api-forge:generate`

Validates the descriptors of an API and generates its services.

```bash
bin/console api-forge:generate <api>
```

| Option | | |
|---|---|---|
| `--strict` | | Fail while review notes remain in the descriptors |
| `--check` | | Write nothing; fail if the generated files are not up to date (CI) |
| `--dir` | `config/api` | Descriptor directory |
| `--output` | project directory | Where to write `src/...` and `config/...` |

Only changed files are written. Generated files that no longer match a descriptor are removed; files
without the "Generated by api-forge:generate" marker are never touched.

## `api-forge:json-to-php`

Converts a JSON example to a PHP array literal and/or a PHPDoc array shape. Accepts documentation
JSON: comments, `{...}` / `[...]` placeholders, trailing commas.

```bash
bin/console api-forge:json-to-php [<json-file>]        # reads stdin without a file
```

| Option | | |
|---|---|---|
| `-s`, `--shape` | | Also print the PHPDoc shape |
| `--shape-only` | | Print only the PHPDoc shape |
| `--tag` | `var` | PHPDoc tag, e.g. `return` or `phpstan-type Order` |
