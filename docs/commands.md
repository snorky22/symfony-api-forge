# Commands

All commands are development tools, provided by the bundle. Run `bin/console <command> --help` for the
details. The default directories come from the `api_forge` configuration (see the README).

## `api-forge:import`

Imports an endpoint from a curl command, and optionally its example response, into the descriptors.

```bash
bin/console api-forge:import <api> <curl-file> [--response=<json-file>]
```

| Option | Default | |
|---|---|---|
| `--response` | none | File with the example JSON response (or an array, `.php`) |
| `--docs` | `<example>.docs.md` | Text capture of the docs page of the response: optional fields, nulls, enums ([The documentation page as text](workflow.md#the-documentation-page-as-text)) |
| `--resource` | first path segment | Resource name |
| `--operation` | inferred from method and path | Operation name |
| `--force` | | Replace an existing operation with the same name |
| `--dir` | `config/api` | Descriptor directory |

Supported curl syntax: single, double and `$'...'` quotes, `\` line continuations, a leading `$ `
prompt, `-X`/`--request` (also `-XPOST`), `-H`, `-d`/`--data`/`--data-raw`/`--data-binary`, `--json`,
`-u`, `-G`, `--url`, `--opt=value`. Unknown options are listed in the review notes.

Instead of a curl file, `<curl-file>` may be an example of another format: a `.php` array holding the request and
the response, for what the docs describe in prose only ([Examples written as arrays](workflow.md#examples-written-as-arrays)).
The JSON arguments of `import-object` and `import-webhook --payload` accept `.php` arrays as well.

## `api-forge:import-object`

Imports resource object examples ("The customer object" in the docs) as the `object` shape of a
resource. Full JSON:API documents are accepted too (API responses, webhook payloads): their `data` is
used. Several examples are merged into one shape: differing types become unions (`int|float`), keys
missing from some examples become optional.

```bash
bin/console api-forge:import-object <api> <resource> <json-file>... [--force] [--dir=...]
```

An existing object shape is kept, unless `--force` is given.

## `api-forge:import-webhook`

Imports webhook documentation into `config/api/<api>/_webhooks.yaml`.

```bash
bin/console api-forge:import-webhook <api> [--events=<markdown-file>] [--payload=<json-file>]...
```

| Option | |
|---|---|
| `--events` | Markdown table of events: event name (in backticks), object sent, description |
| `--payload` | Example payload (repeatable); gives the event name location and, for JSON:API, the event resource |
| `--event` | Event name of the payload, when it cannot be read from it (single `--payload`) |
| `--dir` | Descriptor directory (default `config/api`) |

The resource of each event is derived from the object name of the table ("Subscription invoice
object" → `subscription-invoices`). For JSON:API payloads, the data is compared to the resource object
shape, or gives it when the resource has none.

## `api-forge:generate`

Validates the descriptors of an API and generates its services.

```bash
bin/console api-forge:generate <api>
```

| Option | | |
|---|---|---|
| `--strict` | | Fail while review notes remain in the descriptors |
| `--check` | | Write nothing; fail if the generated files are not up to date (CI) |
| `--dir` | `config/api` | Descriptor directory |
| `--output` | project directory | Where to write `src/...` and `config/...` |

Only changed files are written. Generated files that no longer match a descriptor are removed; files
without the "Generated by api-forge:generate" marker are never touched.

## `api-forge:guide`

The essentials to proceed: without argument, the workflow, the naming of the documentation examples and
the APIs found; with an API, its state (examples, descriptors, review notes, doctor probe, webhooks,
generated code) and the next step, with the commands to copy: the import of each example not imported yet,
the generation, the doctor.

```bash
bin/console api-forge:guide [<api>] [--dir=…] [--output=…] [--fixtures=tests/Fixtures/<api>]
```

## `api-forge:doctor`

Runs the generated doctors (see [Doctor](doctor.md)): environment variables and probe of each API, and its
webhook chain.

```bash
bin/console api-forge:doctor [<api>...] [--ping=URL]
```

| Option | | |
|---|---|---|
| `--ping` | | Public URL of the webhook endpoint to ping (one API only), e.g. a tunnel |

Fails when a problem is found.

## `api-forge:webhook:send`

Simulates a webhook delivery: signs the payload of a file with the secret of the webhook routing
(`framework.webhook.routing`), like the API, and delivers it to `/webhook/<type>` of the application,
in-process. No tunnel, no real event.

```bash
bin/console api-forge:webhook:send <type> <json-file> [--set=path=value]... [--event=name] [--url=URL]
```

| Option | | |
|---|---|---|
| `--set` | | Value to replace in the payload, in dot notation: `meta.custom_data.user_id=42`. Values are JSON (numbers, booleans, `null`, objects), strings otherwise. Repeatable |
| `--event` | | Event name, for APIs sending it in a header |
| `--url` | | Deliver over HTTP to this URL instead, e.g. a running server or a tunnel |

Works with the request parsers generated by api-forge (their signing scheme is known). Fails with a
clear message when the type is unknown, the secret is empty, or the webhook routes are not imported.

## `api-forge:webhook:check`

Checks the webhook chain of the application for each routed type (or the given ones): webhook routes
imported, request parser routed, secret set, RemoteEvent consumer registered, asynchronous transport.

```bash
bin/console api-forge:webhook:check [<type>...] [--ping=URL]
```

| Option | | |
|---|---|---|
| `--ping` | | Public URL to send a signed ping to (one type only), e.g. the tunnel registered in the API's dashboard. Success requires the endpoint's 202: another 2xx means the URL reaches another page (path missing) |

Fails when a problem is found.

## `api-forge:webhook:inbox`

Lists the webhook deliveries received in development (see [Webhooks](webhooks.md#delivery-inbox)), most
recent first, with their origin and outcome.

```bash
bin/console api-forge:webhook:inbox [<type>] [--limit=20] [--show=<id>]
```

## `api-forge:webhook:replay`

Delivers a webhook of the inbox again, signed with the routing secret, in-process.

```bash
bin/console api-forge:webhook:replay <id>       # an id of the inbox, or its beginning
```

## `api-forge:make:resource`

Writes a hand-written REST resource class ([Hand-written REST resources](rest-resources.md)), asking for what is not
given as an option. TODOs mark the shapes to fill from the docs.

```bash
bin/console api-forge:make:resource [<class>] [--actions=list,get] [--no-interaction]
```

| Option | Default | |
|---|---|---|
| `<class>` | asked | Class name, relative to `api_forge.rest.namespace` (`App\API`), e.g. `Paddle\Prices`; written in `api_forge.rest.source_dir` (`src/API`) |
| `--endpoint` | asked, may stay empty | Endpoint from the docs, `https://` optional (`api.paddle.com/prices`): gives the default path, and the base URI of the client configuration |
| `--path` | the endpoint's last segment, else from the class name (`prices`, `license-keys`) | Path of the resource, relative to the base URI |
| `--client` | from the namespace (`paddle.client`) | Service id of the scoped HTTP client |
| `--actions` | `list,get` | Comma-separated: `list`, `get`, `create`, `update`, `delete`; empty for none |
| `--envelope` | none | Key wrapping the responses, e.g. `data` |
| `--docs` | none | URL of the API docs, written as `@see` |
| `--output` | this project | Project directory to write into |

The scoped client is written to `api_forge.rest.config_dir` (`config/packages/<client>.yaml`, e.g. `paddle_client.yaml`)
unless a YAML file there declares it already.

When the class exists, the command asks for its endpoint if the class records none, offers the actions it does not
have yet and adds those chosen (`--endpoint`, `--actions` without interaction); the rest of the file is kept as it is.

## `api-forge:make:webhook`

Writes the hand-written webhooks of an API ([Hand-written webhooks](webhooks.md#hand-written-webhooks)): the request
parser (constants of a signature scheme), the consumer (one method per event), the routing of the webhook type and,
when missing, the route `/webhook/{type}`. Run again on the same API, it adds events to the consumer.

```bash
bin/console api-forge:make:webhook [<api>] [--scheme=paddle] [--events=transaction.completed] [--no-interaction]
```

| Argument / option | Default | |
|---|---|---|
| `<api>` | asked (autocompleted) | API, relative to `api_forge.rest.namespace` (`Paddle`): files in `src/API/Paddle/Webhook` |
| `--scheme` | asked | `paddle`, `stripe`, `github`, `shopify`, `mollie`, `lemonsqueezy`, or `custom` (asks for the constants; interactive only) |
| `--events` | asked (the scheme's suggested) | Comma-separated events to handle |
| `--type` | from the API (`paddle`) | Webhook type: the end of the URL `/webhook/{type}`, the routing key |
| `--output` | this project | Project directory to write into |

Existing files are never overwritten; the routing is written unless the type is routed already.

## `api-forge:call`

Calls a method of an API resource, hand-written or generated, and prints the response as JSON
([Trying a method](rest-resources.md#trying-a-method-api-forgecall)). A real request, with the resource's scoped client.

```bash
bin/console api-forge:call [<class>] [<method>] [<arguments>...] [--max=20]
```

| Argument / option | Default | |
|---|---|---|
| `<class>` | asked (autocompleted) | Class relative to `api_forge.rest.namespace` (`Paddle\Prices`), or fully qualified |
| `<method>` | asked | A public method of the class (`list`, `get`, its own…) |
| `<arguments>` | asked | The method's arguments, in order: JSON when they read as such, else text |
| `--max` | `20` | Items printed at most when the method returns an iterator |

## `api-forge:json-to-php`

Converts a JSON example to a PHP array literal and/or a PHPDoc array shape. Accepts documentation
JSON: comments, `{...}` / `[...]` placeholders, trailing commas.

```bash
bin/console api-forge:json-to-php [<json-file>]        # reads stdin without a file
```

| Option | | |
|---|---|---|
| `-s`, `--shape` | | Also print the PHPDoc shape |
| `--shape-only` | | Print only the PHPDoc shape |
| `--tag` | `var` | PHPDoc tag, e.g. `return` or `phpstan-type Order` |

## `api-forge:yaml-to-php`

Converts a YAML file, typically a descriptor, to a PHP array literal with the same data: short syntax, lists
without keys, multi-line strings (a PHPDoc shape) as nowdocs.

```bash
bin/console api-forge:yaml-to-php config/api/paddle/prices.yaml            # prints the array
bin/console api-forge:yaml-to-php config/api/paddle/prices.yaml -o prices.php   # a file that returns it
```

| Option | | |
|---|---|---|
| `-o`, `--output` | | Write a PHP file (`<?php return [...];`) instead of printing |
| `--force` | | Overwrite the output file (refused by default) |

The code is checked before it is printed: only if its tokens are those of a literal is it evaluated, and the
result must be identical to what the YAML parses to (keys, order and types, including what YAML guesses:
`no`, `1.10`, `~`). Otherwise nothing is written and the command fails. YAML is read as the descriptor
loader reads it: duplicate keys and unknown tags are errors.

Comments can't be carried over: the full-line comments are listed on stderr. The descriptors themselves are
still read from YAML; the converted file is for reading and composing shapes.

## `api-forge:serve`

Runs the local [web interface](web.md) of the workflow: a form for each step.

```bash
bin/console api-forge:serve [--port=8765] [--dry-run]
```

| Option | Default | |
|---|---|---|
| `--port` | `8765` | Port, on `127.0.0.1` |
| `--dry-run` | | Print what would be started, and stop |

Refuses to start in the `prod` environment.
